# SaaS-03B-B0-I-R4-C1-R1 — TypeScript declaration surface reconciliation

## Purpose and inherited state

R4-C1 closed the JavaScript/ESM extraction, but the first strict TypeScript
consumer in the partial 03B-B foundation exposed that the vendored `0.6.0`
artifact shipped runtime modules without declarations. This repair is limited
to declarations and packaging. The partial 03B-B work remains preserved,
uncommitted and outside this repair.

Initial Git gate: `main`, `HEAD == origin/main ==
084ba2b38008f412747d8c147c9af92c9255ed2a`, with only the declared partial
03B-B Functions files dirty. No reset, restore, checkout, stash or clean was
used.

## Defect and authority decision

The reproduced defect was TypeScript `TS7016` for the package root and public
subpaths. JavaScript plus JSDoc remains the sole physical contract authority.
Declarations are deterministic derived artifacts generated by TypeScript; the
runtime was not migrated to TypeScript and no hand-maintained duplicate model
was introduced.

The declaration contract is fail-closed: strict NodeNext consumers resolve all
eight public entries; declarations contain no `any`; internal modules remain
blocked by the export map; invalid literal use is rejected; and regeneration
reproduces every committed declaration byte-for-byte.

## Implementation and public API

Package version `0.6.0` became `0.6.1`. This is a SemVer PATCH because runtime
API and semantics are unchanged while a defective compatibility surface is
repaired. The manifest now defines `types`, typed conditions for the eight
explicit exports, includes `types/`, and provides `build:types` and
`check:types`. TypeScript `5.9.3` is build-only; runtime dependencies remain
zero.

`tsconfig.types.json` emits declarations from checked JavaScript under strict
NodeNext rules. Ten runtime files received JSDoc-only annotations needed to
remove inferred `any`; values, order, freezing, exports and behavior did not
change. Twenty-eight `.d.ts` files are committed derived artifacts with zero
`any` occurrences.

The declaration surface covers the root plus `domain`, `persistence`,
`validation`, `commands`, `authority`, `audit` and `errors`. Public exports stay
explicit and `internal` remains private.
